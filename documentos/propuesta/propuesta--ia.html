1. Objetivo

Incorporar un asistente conversacional en zuitch.com que ayude a los usuarios a encontrar productos, páginas y grupos, responda dudas de uso con documentación controlada, y permita al superadmin (Aldo) revisar conversaciones y corregir respuestas sin reentrenar un modelo desde cero.

2. Qué se entrega

Usuario

Asistente flotante

Botón abajo a la derecha (sesión iniciada). Abre el chat, lista conversaciones, crea chat nuevo, borra uno o borra todo el historial.

Intención

Clasifica antes de buscar

Primero decide: producto, página, grupo, soporte o chat. Solo consulta lo preciso. Si es charla o duda sin catálogo, la IA responde sin tocar MySQL de mercado.

Catálogo

Recomendaciones reales

Como máximo 6 fichas (nombre, precio si aplica, una línea, enlace). No se mete el catálogo entero en el prompt. Funciona hoy (28 productos) y a 10.000 filas.

Admin

Panel Zuitch AI

Prompts editables, documentación de soporte, seguimiento de todos los chats, calificación de usuarios y OK / Corregir solo para el superadmin.

3. Arquitectura (cómo funciona)

El modelo es la API de ChatGPT (compatible con chat/completions). Zuitch ya tiene openai_token en AI Settings. El cliente llama a una URL configurable: mañana puede apuntar a un servidor propio (vLLM, Ollama u otro) sin reescribir el widget.

Usuario escribe → Prompt de intención → Consulta solo 1 fuente → Prompt de respuesta → Chat + fichas

Etiquetas de intención

  • producto / pagina / grupo — consulta solo esa tabla; máximo 6 fichas.
  • soporte — busca en la documentación de funciones (admin-cp); máximo 3 trozos.
  • chat — no consulta base ni docs; responde con el prompt.

Ejemplos

  • “busco un auto mercedes benz a10” → producto
  • “hay alguna página de concesionarios” → pagina
  • “grupos para hablar de autos” → grupo
  • “cómo publico un producto” → soporte
  • “hola” / opinión suelta → chat

Volumen actual de la plataforma

~28 productos · ~382 páginas · 1 grupo · ~12.500 posts · ~45.000 usuarios. Los posts no entran en la búsqueda del asistente.

4. Búsqueda inteligente sin matar tokens, RAM ni CPU

Con 10.000 productos la IA no los “lee”. MySQL rankea y solo se envían hasta 6 fichas cortas. Presupuesto fijo por mensaje aunque el catálogo crezca.

Presupuesto de tokens

Sistema ~400 · últimos 6 mensajes ~1.200 · fichas (si hay) ~600 · pregunta del usuario. Si no hay coincidencias, las fichas no se envían.

Caso Mercedes “a10”

Limpia la frase, prueba equivalentes cortos (auto→carro/coche), rankea por palabras en nombre/descripción y, solo si una palabra no existe, corrige entre ~20 candidatos (a10→a180).

  1. Limpieza en PHP (minúsculas, sin tildes, quitar “busco”, “un”).
  2. Lista corta de equivalentes (no un diccionario enorme).
  3. Una consulta rankeada; top 6.
  4. Corrección de tipografía solo si hace falta; no se recorre el catálogo en memoria.
  5. Al crecer el catálogo: índice FULLTEXT (fase posterior). El tope sigue siendo 6.

5. Prompts editables (admin-cp)

Dos prompts + documentación de soporte. El admin los cambia sin tocar código.

Prompt de intención

Eres el clasificador de Zuitch AI. Lee el mensaje del usuario y responde una sola palabra, sin explicación: - producto: quiere comprar, ver precio o que le recomienden un artículo del mercado. - pagina: busca una página, negocio, tienda o perfil de página. - grupo: busca un grupo o comunidad. - soporte: pregunta cómo se usa Zuitch (cuenta, contraseña, publicar, comprar, páginas, grupos u otra función de la plataforma). - chat: saludo, opinión o charla que no pide catálogo ni ayuda de uso. Si pide más de una cosa, elige la principal. No inventes otra etiqueta.

Prompt de respuesta

Eres Zuitch AI, el asistente de zuitch.com. Responde en el idioma del usuario, breve y claro. Si {correcciones} trae una respuesta aprobada por el superadmin y la pregunta se parece, usa esa respuesta. Esa versión manda sobre tu criterio. Si {contexto} está vacío, responde con la conversación. No inventes productos, páginas, grupos, precios ni pasos que no estén en la documentación. Si {contexto} trae fichas de catálogo, recomienda solo esas. Di el nombre, el precio si viene y el enlace. Si una palabra se corrigió, menciónalo en una frase. Si {contexto} trae documentación, explica solo con esos pasos. No completes con funciones que no aparezcan ahí. No leas mensajes privados, pedidos ni datos de otros usuarios. No publiques ni compres por el usuario.

Documentación de soporte

Texto en admin-cp, partido por títulos (cómo crear página, publicar producto, etc.). En soporte se rankean trozos y entran 3. No se lee el código ni las publicaciones del feed.

6. Calificación, corrección y seguimiento

Cualquier usuario

Útil / No útil + comentario

Se guarda y se lista en admin-cp. No se inyecta al modelo. Sirve para que Aldo decida qué corregir.

Solo superadmin

OK / Corregir

Marca la respuesta como ejemplo o escribe lo que debió decir. Eso sí entra en {correcciones} en preguntas parecidas y manda sobre el modelo.

Seguimiento de conversaciones

En admin-cp, solo el superadmin ve todos los chats de Zuitch AI (no mensajes privados entre usuarios): usuario, fecha, cantidad de chats, recorte del último mensaje; al abrir, el hilo completo con calificaciones y botones OK / Corregir. Buscador por nombre o palabra. Si el usuario borra un chat, también sale del panel.

7. Configuración en admin-cp

Página nueva Zuitch AI (junto a AI Settings), sin mezclarse con la IA que genera posts, blogs o avatares.

  • Activar Zuitch AI
  • URL base (por defecto https://api.openai.com/v1) — lista para modelo propio
  • Modelo (p. ej. gpt-4o-mini)
  • Clave: la de openai_token o una clave dedicada
  • Prompt de intención, prompt de respuesta y documentación de soporte
  • Seguimiento de chats + OK / Corregir
  • Imágenes on/off (jpg, png, webp) y lista de formatos de archivo
  • Máximo de fichas (6) y tope de mensajes por usuario al día

Imágenes y archivos en el primer ciclo

La configuración de imágenes/formatos queda en el panel. PDF y Office (extracción de texto) e índice FULLTEXT no entran en las ~18 h del primer ciclo; se dejan para después. La URL del modelo propio sí queda desde el día uno.
