Leyenda de tiempos

Los minutos/horas son tiempo activo (estás delante del teclado o en una llamada). La propagación DNS (0,5–24 h) y la revisión de Apple (días) se listan aparte: no las sumes a tu carga de trabajo, pero sí al calendario del proyecto.

2.A — Lo que haces tú (plataformas) — todo el módulo

Bloque A — Anti-bots

# Quién Plataforma Tiempo Qué hacer (primera vez)
1 Tú Cloudflare 20–30 min Crear cuenta y añadir la zona

Entra a dash.cloudflare.com, crea cuenta (o inicia sesión), pulsa “Add a site”, escribe zuitch.com, elige plan Free (u otro que prefieras) y deja que Cloudflare escanee el DNS. No cambies nameservers todavía si no tienes ventana acordada.

2 Tú Registrador del dominio 15–25 min Cambiar nameservers (ventana acordada)

Cloudflare te mostrará 2 nameservers. En el panel donde compraste el dominio, sustituye los nameservers por los de Cloudflare. Coordina un horario por si hay un corte breve de DNS.

3 Espera DNS internet 0,5–24 h Propagación DNS

No es trabajo activo. En Cloudflare el estado pasa a “Active” cuando termina. Mientras esperas puedes avanzar Apple/Meta/reCAPTCHA/GitHub.

4 Tú Cloudflare DNS 10 min Proxy naranja en hosts web

zuitch.com, www y subdominios web acordados con nube naranja (Proxied). No pongas naranja en MX ni en lo que deba quedar DNS only (gris).

5 Tú Cloudflare 15–20 min Zone ID + API Token (canal seguro)

Overview → Zone ID. My Profile → API Tokens → Create Token con permisos de zona/firewall según pida Cursor. Envíalos por canal seguro.

6 Tú Google reCAPTCHA 15–20 min Crear reCAPTCHA v2 y copiar keys

https://www.google.com/recaptcha/admin → reCAPTCHA v2 → dominios zuitch.com y www.zuitch.com. Envía Site Key + Secret Key por canal seguro.

7 Tú GitHub 10 min Invitar colaborador al repositorio

Settings → Collaborators → Invite al usuario que trabaja con Cursor.
8 Tú Coordinación 15 min Ventana DNS + smoke test anti-bots

Tras “Active”: home, login, formulario con captcha y admin. Reporta falsos positivos de bots.

Subtotal tú — solo bloque A (anti-bots)

~2,5–4 h activas + espera DNS. No se suma aquí el tiempo de Cursor.

Bloque B — App iOS (portales y QA)

# Quién Plataforma Tiempo Qué hacer (primera vez)
9 Tú Apple Developer 45–90 min Credenciales Sign in with Apple para el servidor

Team ID, Services ID, Key con Sign In with Apple, archivo .p8 (una sola descarga). Envía Key ID + Team ID + Services ID + .p8 por canal seguro (revoke al borrar cuenta).

10 Tú Meta / Facebook 30–60 min App ID, secret y usuarios de prueba

Confirma App ID/Secret; añade usuarios sandbox si hace falta. Cursor integra en el backend.

11 Tú Coordinación iOS 30–60 min Handoff técnico al equipo de la app

Header X-Zuitch-Client: ios-webview en set-browser-cookie; identity token Apple al social-login; pruebas en TestFlight/iPhone.

12 Tú Admin / BD 20–40 min Usuarios de prueba (normal, Apple, Facebook)

Cuentas documentadas para QA y App Review.
13 Tú Live / ops 30–60 min Usuario + transmisión Live de prueba

Stream HTTPS de prueba. Si falla VM/firewall/RTMP es ops, no solo código.

14 Tú TestFlight / iPhone 60–90 min QA con checklist de aceptación

Login Apple sin password extra; delete social; WebView estable; gate digitales; físicos/DHL OK; sin GA; report/block; Facebook; Live.

15 Tú App Privacy 20–30 min Declaración de contactos

Match-only (§4.7 de la propuesta App iOS). El equipo iOS completa App Privacy; tú confirmas que el backend no guarda la agenda.

16 Espera App Store Review días Revisión humana de Apple

No es tiempo activo tuyo ni de Cursor.

Subtotal tú — solo bloque B (iOS)

~3,5–6,5 h activas. App Review aparte (espera).

Subtotal tú — módulo fusionado completo

~5,5–10 h = bloque A (2,5–4) + bloque B (3,5–6,5). Esto es solo tu tiempo; Cursor va en la sección siguiente.

# Quién Ámbito Tiempo Qué implementa

Home, login, captcha, admin. Hasta 2 h de ajuste incluidas.

2.D — Qué NO hace Cursor en este módulo

  • Crear cuentas Cloudflare/Google/Apple/Meta ni cambiar nameservers.
  • Código nativo iOS, TestFlight, App Store Connect ni garantizar App Review.
  • StoreKit/IAP, cambios DHL, pentest, PHP upgrade, CI/CD, backups offsite.
  • Arreglar solo con código una caída de infra Live (VM/firewall/RTMP).

3. Módulo UX/UI — paso a paso

Widget de sugerencias solo para superadministradores (selector de elementos, captura, adjuntos, historial en Admin) + botón WhatsApp opcional en posts de Páginas.

Cobrar: USD 240 lista / 180 desc. Tú: ~1–1,5 h + 1 h capacitación Cursor: 8–14 h

3.A — Lo que haces tú

# Quién Plataforma Tiempo Qué hacer (primera vez)
1 Tú zuitch.com 5 min Confirmar cuenta superadmin de prueba

Inicia sesión con un usuario que sea superadministrador. El widget solo aparece para ese rol. Si no tienes uno, créalo o eleva un usuario de prueba desde Admin.

2 Tú Web pública 30–45 min Probar el widget de sugerencias

Abre el botón flotante. Crea un reporte tipo Sugerencia y otro tipo Error. Prueba modo “Abierta” y “Seleccionar elemento” (clic sobre un botón o bloque). Usa captura de pantalla completa, pega una imagen con Ctrl+V y sube un adjunto. Asigna prioridad alta o crítica al menos una vez.

3 Tú Admin-CP 15–20 min Validar histórico en Admin

Entra a https://zuitch.com/admin-cp, abre la sección nueva de sugerencias. Filtra por tipo/prioridad/estado; abre el detalle; usa el enlace a la URL reportada; cambia estado a “en progreso” y añade una nota interna de prueba.

4 Tú Ajustes de Página 10–15 min Configurar WhatsApp en una Página de prueba

Edita una Página: pon un número de WhatsApp válido e activa el interruptor “mostrar en publicaciones”. Publica un post desde esa Página y comprueba que aparece el botón; desactiva el interruptor y verifica que desaparece. Por defecto debe estar oculto en Páginas sin configurar.

5 Tú Videollamada 60 min Capacitación incluida (1 hora)

Sesión remota agendada tras la entrega: crear sugerencias, seleccionar elementos, captura completa, adjuntos, y gestionar prioridad/estado en Admin.

Subtotal tú — UX/UI

~2–2,5 h contando la capacitación (o ~1–1,5 h solo de pruebas si la capacitación se agenda aparte).

3.B — Lo que hace Cursor

# Quién Ámbito Tiempo Qué implementa
1 Cursor Frontend 3–5 h Widget FAB + modal + selector + captura + adjuntos

Solo visible para superadmin autenticado. Tipos sugerencia/error; modos abierta/seleccionar elemento; metadatos automáticos (URL, navegador, SO, dispositivo, viewport, DPR, selector CSS); captura best-effort de página completa; hasta 5 adjuntos.

2 Cursor Backend / BD 2–3 h Almacenamiento de tickets y archivos

Tablas/endpoints para sugerencias, prioridades, estados, usuario emisor y adjuntos asociados.

3 Cursor Admin-CP 2–3 h Sección de histórico

Listado, filtros, detalle, cambio de estado/prioridad, nota interna, link a la página reportada.

4 Cursor Páginas / posts 1–2 h WhatsApp opcional

Campo número + interruptor en ajustes de Página; botón wa.me solo en posts de esa Página si está activo y el número es válido; oculto por defecto.

5 Cursor Post-entrega 0,5–1 h Ajustes menores dentro del alcance

Correcciones de UI o bugs reportados en los primeros días tras la entrega.

Subtotal Cursor — UX/UI

~8–14 h de desarrollo e integración sobre WoWonder.

3.C — Qué NO hace Cursor aquí

  • Rediseño general del sitio ni app nativa iOS/Android.
  • WhatsApp en perfiles de usuario o grupos (solo Páginas).
  • Roles de moderador (solo superadministradores).
  • Notificaciones externas (email/Telegram) ni soporte mensual.

4. Cronograma sugerido (calendario)

Plan de ~2 semanas. Primero el módulo fusionado (anti-bots → iOS web); después UX/UI.

  1. Día 1 — Preparación de cuentas (tu tiempo) Cloudflare, reCAPTCHA, GitHub, Apple .p8, Meta App ID/secret. Tú: ~2–3,5 h. Cursor: 0 h.
  2. Días 2–3 — Bloque A anti-bots Nameservers + DNS. Cursor: SSL/bots/WAF/captcha/Git/hardening (~3–5 h). Tú: smoke (~1 h) + espera DNS.
  3. Días 4–10 — Bloque B App iOS web Cursor: auth, delete, cookies, gate, tracking, FB, Live (~12–20 h). Tú: handoff + usuarios + Live + QA iPhone (~3,5–6,5 h).
  4. Días 10–13 — Módulo UX/UI Cursor: widget + Admin + WhatsApp (~8–14 h). Tú: pruebas (~1–1,5 h) + capacitación 1 h.
  5. Luego — App Review Espera externa (días). No suma horas activas tuyas ni de Cursor.

Bloqueadores típicos (alargan el calendario, no las horas de código)

Nameservers sin cambiar; keys reCAPTCHA o .p8 no enviadas; Meta app en modo restringido sin usuarios de prueba; equipo iOS sin header X-Zuitch-Client; Live caído por firewall. Mientras falte un acceso, Cursor se queda a medias.
