1. Objetivo

Reducir tráfico automatizado y abuso sobre la plataforma social, filtrando amenazas antes de que lleguen al servidor (Cloudflare), reforzando formularios públicos (reCAPTCHA) y dejando el código versionado de forma limpia en Git.

2. Alcance incluido

Módulo A

Cloudflare

Configuración técnica tras el alta del cliente: SSL Full (Strict), protección anti-bots, WAF básico y rate limit en rutas sensibles.

Módulo B

reCAPTCHA + Git + hardening

Activación de claves en Admin, formularios verificados, Git limpio y refuerzo básico del origen (headers y archivos sensibles).

A — Cloudflare (anti-bots en el borde)

  • Revisión de DNS/proxy naranja en hosts web acordados (zuitch.com, www y subdominios que indiquen).
  • SSL/TLS en modo Full (Strict).
  • Bot Fight / reglas anti-bots según el plan de Cloudflare del cliente.
  • WAF managed rules básicas + rate limit en login/registro, /requests.php y /api*.
  • Ajuste de excepciones si la app o APIs legítimas reciben falsos positivos (incluido en el paquete, ver condiciones).

B — Google reCAPTCHA

  • Activar/verificar Site Key y Secret Key en el panel Admin.
  • Comprobar formularios ya contemplados: registro, contacto, recuperación de contraseña y blogs.

C — Git y versionamiento

  • Refuerzo de .gitignore (sin config.php, SQL, zips, uploads, logs).
  • Flujo simple: rama → cambios → merge → deploy en Plesk.
  • Checklist breve pre-deploy (backup + smoke test).

D — Hardening básico del origen

  • Headers: X-Frame-Options, X-Content-Type-Options (y alineación con HSTS existente).
  • Bloqueo o retiro de exposición HTTP de backups/SQL/zips en el webroot.
  • Revisión rápida del control de intentos de login fallidos.

Pruebas de entrega

  • Smoke test: home, login, un formulario con captcha y acceso admin.
  • Hasta 2 horas de ajustes post-entrega por falsos positivos de bots.

3. Lo que prepara el cliente

Sin estos datos no se puede cerrar la configuración. Se entregan por canal seguro (no en este documento).

  • Cloudflare: crear cuenta, añadir zuitch.com, cambiar nameservers en el registrador, activar proxy naranja y enviar Zone ID + API Token.
  • reCAPTCHA v2: Site Key + Secret Key con dominios zuitch.com y www.zuitch.com.
  • GitHub: acceso de colaborador al repositorio del proyecto.
  • Ventana DNS: horario acordado para el cambio de nameservers.

Costos a cargo del cliente

Plan de Cloudflare (Free u otro que elijan), cuenta Google para reCAPTCHA y el dominio. El paquete de USD 350 cubre solo el trabajo técnico de implementación descrito.

6. Fuera de alcance

  • Migración o actualización de versión de PHP (p. ej. 7.4 → 8.x).
  • Auditoría / pentest formal certificado.
  • GitHub Actions, deploy automático o monitoreo 24/7.
  • CSP agresiva, rediseño de seguridad de toda la API o del livestream Node.
  • Backups offsite de media o base de datos.
  • Soporte mensual recurrente (salvo las 2 h de ajuste incluidas).
  • Cualquier trabajo no listado en el alcance: requiere propuesta aparte.

7. Condiciones

  • Implementación sobre la plataforma actual WoWonder de zuitch.com (Plesk).
  • El cliente completa el alta de Cloudflare, reCAPTCHA y acceso Git antes o durante el inicio de trabajos.
  • El cambio de nameservers puede implicar una ventana breve de propagación DNS; se coordina horario.
  • Las 2 horas de ajuste post-entrega cubren falsos positivos de bots; el resto se cotiza aparte.
